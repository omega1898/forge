# Open coding standards and static checkers for managed, web and scripting languages (Python, Java, C#/.NET, JS/TS, Shell, PowerShell, VBA, Kotlin, Swift, PHP, Ruby)

Research date: 2026-11-05. Method note: in this session `wiki.sei.cmu.edu`, `learn.microsoft.com`, `errorprone.info`, `cmu-sei.github.io`, `github.com` HTML pages and the GitHub REST API were blocked (DNS failure or proxy 403). I used `raw.githubusercontent.com` copies of LICENSE files, source files and docs (fetched with curl, then grepped), the PyPI, npm and NuGet registry APIs for versions, dates and license metadata, and web search. Counts marked "(grep count)" come from my own grep of the fetched file at its current default branch. They are approximate: they may include deprecated or removed entries. Raw-file URLs are cited as fetched.

## Python: PEPs, Google style, ruff, pylint, flake8, bandit, mypy/pyright, semgrep rules, pip-audit

### Takeaway
The Python standards text can be redistributed: PEP 8, PEP 257 and PEP 484 are public domain, and the Google Python Style Guide is CC-BY 3.0. Every core checker is under a permissive or weak-copyleft license, except pylint, which is GPL-2.0. Ruff (MIT, about 984 rule codes) re-implements pyflakes (F), pycodestyle (E/W), bugbear (B), bandit (S, using the same numbers as bandit's B codes), a subset of pylint (PL*) and roughly 55 other plugin families, and it emits SARIF natively. Bandit is the only Python linter here that attaches CWE IDs to each issue. The Semgrep-maintained rules have been under a restrictive non-OSI license since December 2024, so you should not ship them in a product.

### Inferences
- For a deterministic offline assistant, ruff can be the single Python lint engine for style plus most correctness checks. Its S-codes share bandit's numbering, so you can attach bandit's CWE table to ruff S-findings with a static lookup (S602 → B602 → CWE-78). Ruff itself emits no CWE; I found no CWE field in ruff's code tables.
- pylint's GPL-2.0 matters only if you embed or redistribute it. Running it as a separate process is the usual way to avoid license coupling, but this is a legal judgment, not something I verified.
- pip-audit is not offline by design: every service it lists is a network API. For offline use, mirror the CC-BY-4.0 PyPA advisory DB, or an OSV export, and match versions locally.
- Pin tool versions and disable preview rules (ruff has preview-group rules) to keep results reproducible across upgrades.

- I could not count the current ruff rules split by stable, preview and deprecated status: `codes.rs` no longer carries `RuleGroup` annotations in a greppable form, and docs.astral.sh was not fetched.
- I did not verify whether bandit's SARIF output includes the CWE taxonomy.
- I could not fetch the full Semgrep Rules License text (semgrep.dev/legal/rules-license). The repo LICENSE file and Semgrep's announcement disagree. Treat the registry rules as restricted.
- I did not research flake8 plugin licenses one by one (bugbear, flake8-bandit and others).

## Java: SEI CERT Java, Google Java Style, SpotBugs + FindSecBugs, PMD/CPD, Checkstyle, Error Prone, NullAway

### Takeaway
The SEI CERT coding standards, Java included, are now published on GitHub under CC BY 4.0 for the text and MIT for the code examples (2026 LICENSE). That replaces the old wiki terms, under which external or commercial reproduction needed permission. Google Java Style is CC-BY 3.0. The tools are LGPL (SpotBugs 2.1, FindSecBugs 3.0, Checkstyle 2.1), BSD-style (PMD) or Apache/MIT (Error Prone, NullAway, google-java-format). SpotBugs, PMD and Checkstyle emit SARIF natively; Error Prone has no SARIF output that I could confirm. CWE tags exist on 129 of 518 SpotBugs patterns and 136 of 144 FindSecBugs patterns.

### Inferences
- With the CC BY 4.0 relicensing, CERT Java rule text (titles, descriptions, noncompliant and compliant examples) can be bundled with attribution into an offline assistant's knowledge base. This is a major change from the wiki-era terms. The CERT trademark notice still applies.
- For CWE-tagged Java security findings, SpotBugs + FindSecBugs carry the most explicit CWE metadata. PMD's security category is very thin (2 rules), so PMD is mainly a style/design/errorprone engine plus CPD.
- Error Prone and NullAway run inside javac, so they need a compilable build. SpotBugs needs compiled bytecode. Checkstyle and PMD work on source alone, which makes them easier to run deterministically on code snippets.

- No SARIF output in Error Prone was found. Not confirmed absent, because errorprone.info was unreachable.

## C#/.NET: Roslyn CA/IDE analyzers, StyleCop.Analyzers, SonarAnalyzer.CSharp, Security Code Scan

### Takeaway
Microsoft's analyzers (CAxxxx quality, IDExxxx style) are MIT and ship inside the .NET SDK; `Microsoft.CodeAnalysis.NetAnalyzers` now lives in dotnet/sdk. Any Roslyn analyzer's diagnostics can be written as SARIF 2.1 through the compiler's `ErrorLog` option. StyleCop.Analyzers is MIT but has had no stable release since 2019; 1.3.x betas are still published. SonarAnalyzer.CSharp has been under the non-OSI Sonar Source-Available License since late 2024. Security Code Scan (LGPL-3.0) has not released since September 2022.
